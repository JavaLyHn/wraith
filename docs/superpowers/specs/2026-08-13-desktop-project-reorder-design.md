# 桌面项目置顶与手动排序设计

## 目标

让桌面端左侧项目列表支持收藏组和普通组内的手动排序。用户可以拖拽项目行，也可以通过项目菜单执行“上移/下移”；顺序在本地 settings.json 持久化，重启后保持。

## 现状与兼容性

- 项目已经有 `starred?: boolean` 字段和 `setProjectStarred` IPC；收藏项目会显示在“重点”区域。
- 现有项目使用 `lastUsedAt` 倒序作为默认顺序。
- 旧 settings 没有顺序字段，升级时必须保持可读；首次读取时按当前列表顺序推导稳定顺序。

## 数据模型

在 `ProjectEntry` 增加可选 `order?: number`。它只表达同一收藏分组内的相对顺序，不暴露给 renderer。

- `starred === true` 的项目组成收藏组，其他项目组成普通组。
- 每组按 `order` 升序；缺失或重复的 order 按当前 `lastUsedAt` 倒序稳定补齐。
- 新项目追加到普通组末尾；收藏项目追加到收藏组末尾；取消收藏后追加到普通组末尾。
- 重排只交换/重编号同组项目的 order，不改变 `starred`、`lastUsedAt` 或项目名称。

## 交互

- 项目行支持 HTML5 drag-and-drop；拖拽目标只能是同一分组的项目行，跨组拖拽不改变收藏状态，也不执行重排。
- 项目更多菜单新增“上移”和“下移”；在组首/组尾分别禁用对应按钮。
- 搜索结果只做临时过滤，不改变顺序；过滤后仍按原组内顺序显示。
- 收藏星标仍是唯一改变分组的入口；收藏/取消收藏后刷新列表并保持该项目在新组末尾。
- 当前项目、缺失目录和忙碌状态不阻止拖拽排序；排序是本地元数据操作，不切换项目。

## IPC 与错误处理

- 新增窄 IPC `wraith:reorderProject`，参数为项目路径、新索引和分组标识，主进程校验项目存在于 settings 且目标索引在组范围内后持久化。
- preload 仅暴露类型化 `reorderProject(path, targetIndex)` 方法；renderer 不直接访问文件系统。
- 持久化失败沿用 settings 的 best-effort 约定，但 renderer 只有在 IPC 成功返回后更新显示；失败时重新拉取列表，避免出现假顺序。

## 验证

- 纯函数测试：分组排序、旧数据补序、组内移动、边界索引、跨组拒绝。
- settings 测试：order 持久化、追加规则、收藏切组、重排后其他字段不变。
- 组件测试：菜单按钮禁用边界、点击上移/下移、拖拽同组调用、跨组不调用、搜索不改顺序。
- 运行 `cd desktop && npx.cmd vitest run` 与 `npx.cmd tsc --noEmit`。
