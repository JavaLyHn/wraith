# 深模块设计（Codebase Design）

## 概述

设计**深模块**：小接口背后藏大量行为，落在干净的接缝处，可透过接口测试。在任何设计或重构代码的地方使用这套语言与原则。

目标：给调用方**杠杆**、给维护者**局部性**、给所有人**可测性**。

## 词汇表

用词要精确，不要用「组件」「服务」「API」「边界」替代——一致的语言是这套方法的全部意义。

- **模块（Module）**——有接口和实现的东西。刻意尺度无关：函数、类、包、跨层切片。*避免*：unit / component / service。
- **接口（Interface）**——调用方正确使用模块所必须知道的一切：类型签名、不变量、顺序约束、错误模式、必需配置、性能特征。*避免*：API / signature（太窄，只指类型表面）。
- **实现（Implementation）**——模块内部的代码体。与**适配器**区分：一个小适配器可以带大实现（Postgres repo），一个大适配器可以带小实现（内存 fake）。讨论接缝时说「适配器」，讨论内部时说「实现」。
- **深度（Depth）**——接口处的杠杆：调用方/测试每学一单位接口能驱动多少行为。**深**=小接口背后大行为，**浅**=接口几乎和实现一样复杂。
- **接缝（Seam，Michael Feathers）**——不用改那个位置就能改行为的地方，模块接口所在之处。接缝放哪是独立的设计决策，与接缝背后放什么分开。*避免*：boundary（与 DDD bounded context 冲突）。
- **适配器（Adapter）**——在接缝处满足接口的具体物。描述*角色*（填哪个槽），不描述实体（里面是什么）。
- **杠杆（Leverage）**——调用方从深度中得到的东西：每学一单位接口换更多能力。一个实现回报 N 个调用点 + M 个测试。
- **局部性（Locality）**——维护者从深度中得到的东西：改动、bug、知识、验证集中在一处而非散落各调用点。修一次，处处修。

## 深与浅

深模块=小接口+大实现：

```
┌─────────────────────┐
│   Small Interface   │  ← 方法少、参数简单
├─────────────────────┤
│  Deep Implementation│  ← 复杂逻辑藏在里头
└─────────────────────┘
```

浅模块=大接口+小实现（要避免）：

```
┌─────────────────────────┐
│     Large Interface    │  ← 方法多、参数复杂
├─────────────────────────┤
│  Thin Implementation   │  ← 只是转发
└─────────────────────────┘
```

设计接口时自问：能不能减少方法数？能不能简化参数？能不能把更多复杂度藏进去？

## 原则

- **深度是接口的属性，不是实现的属性。**深模块内部可以由小而可测可替换的零件组成——它们不进接口。模块可以有**内部接缝**（实现私有、给自己的测试用）和**外部接缝**（接口处）。
- **删除测试（Deletion test）。**想象删掉这个模块。复杂度消失=它是个转发层。复杂度在 N 个调用点重新出现=它挣到了自己的位置。
- **接口即测试面。**调用方和测试穿过同一道接缝。如果你想*绕过*接口去测，模块形状大概不对。
- **一个适配器只意味着假想的接缝；两个适配器才意味着真正的接缝。**别引入接缝，除非真有东西在跨它变化。

## 为可测性设计

好接口让测试自然：

1. **接受依赖，不要自己创建。**

   ```typescript
   // 可测
   function processOrder(order, paymentGateway) {}
   // 难测
   function processOrder(order) {
     const gateway = new StripeGateway();
   }
   ```

2. **返回结果，不要产出副作用。**

   ```typescript
   // 可测
   function calculateDiscount(cart): Discount {}
   // 难测
   function applyDiscount(cart): void {
     cart.total -= discount;
   }
   ```

3. **小表面积。**方法少=要写的测试少。参数少=测试 setup 简单。

## 关系

- 一个**模块**恰好有一个**接口**（它给调用方和测试看的表面）。
- **深度**是**模块**相对于其**接口**的属性。
- **接缝**是**模块**的**接口**所在之处。
- **适配器**坐落在**接缝**上并满足**接口**。
- **深度**为调用方产出**杠杆**、为维护者产出**局部性**。

## 拒绝的框定

- **深度=实现行数/接口行数的比值（Ousterhout）**：奖励往实现里灌水。这里用「深度=杠杆」。
- **「接口」=TypeScript 的 `interface` 关键字或类的公开方法**：太窄——接口在这里指调用方必须知道的每一个事实。
- **「边界」**：与 DDD bounded context 冲突。说**接缝**或**接口**。
