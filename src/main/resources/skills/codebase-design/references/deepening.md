# 加深（Deepening）

如何安全地加深一簇浅模块，已知其依赖。假设已读 SKILL.md 的词汇——**模块**、**接口**、**接缝**、**适配器**。

## 依赖分类

评估加深候选时，把它的依赖分类。类别决定加深后的模块如何跨接缝测试。

### 1. 进程内

纯计算、内存状态、无 I/O。永远可加深——合并模块，直接透过新接口测试。不需要适配器。

### 2. 本地可替代

依赖有本地测试替身（PGLite 代 Postgres、内存文件系统代 FS）。有替身就能加深。加深后的模块用替身在测试套件里跑。接缝是内部的；模块外部接口没有端口。

### 3. 远程但自有（端口与适配器）

跨网络边界的自有服务（微服务、内部 API）。在接缝处定义**端口**（接口）。深模块拥有逻辑；传输作为**适配器**注入。测试用内存适配器；生产用 HTTP/gRPC/队列适配器。

建议形态：*「在接缝处定义端口，为生产实现 HTTP 适配器、为测试实现内存适配器，让逻辑落在单个深模块里——即便它跨网络部署。」*

### 4. 真正外部（Mock）

不掌握的第三方服务（Stripe、Twilio 等）。加深后的模块把外部依赖作为注入端口；测试提供 mock 适配器。

## 接缝纪律

- **一个适配器意味着假想的接缝。两个适配器才意味着真正的。**除非至少两个适配器站得住脚（典型是生产+测试），否则别引入端口。单适配器接缝只是间接层。
- **内部接缝 vs 外部接缝。**深模块可以有内部接缝（实现私有、给自己的测试用）和外部接缝（接口处）。不要因为测试要用就把内部接缝从接口暴露出去。

## 测试策略：替换而非叠加

- 浅模块上的旧单测，等加深模块接口处的测试就绪就成了废料——删掉。
- 在加深模块接口处写新测试。**接口即测试面**。
- 测试断言透过接口的可见结果，不断言内部状态。
- 测试应挺过内部重构——它们描述行为，不描述实现。如果一个测试因为实现变了就得改，它测到了接口之外。
