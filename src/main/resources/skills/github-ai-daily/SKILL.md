# GitHub AI 日报

## 你的角色：解读者，不是生成者

报告**已经算好了**，由每天定时运行的取数脚本产出（macOS 走 launchd，Windows 走任务计划程序），
落在**文档资料库**里，文件名形如 `GitHub-AI-日报-2026-08-05.md`。

你的工作是把它读出来、加上人话点评，**不是自己去查 GitHub、更不是凭印象编一份**。
榜单里每个数字都来自快照做差，不经过任何模型。这是设计上的红线：
**一个数字都不要改、不要重算、不要"顺手修正"。**

## 步骤

1. `documents_read('GitHub-AI-日报-<今天日期>.md')`，日期格式 `YYYY-MM-DD`。

   这个工具读的是跨项目的资料库，**不受当前项目限制** —— 在哪个项目下问都一样。

2. **读到了** → 原样保留全部榜单与数字，在每张榜后面补三行中文点评：
   - Top 3 为什么会火（结合简介、赛道、最近的行业动向）
   - 值不值得跟：能直接用的工程，还是只是概念演示
   - 和读者手上的事有没有关系（做 agent / RAG / 工程化 的人该不该点进去看）

   最后把**报告全文 + 你的点评**一起输出。

3. **读不到** → 用 `documents_list` 看资料库里最近有哪几份日报。
   - 有更早的日报 → 可以读最近那份，但**必须在开头说清楚这是哪一天的、不是今天的**。
   - 一份都没有 → 明说「还没有日报」，并提示：取数脚本可能还没跑完或失败了，
     日志在仓库的 `.ghai/run.log`。然后**结束**。

## 绝对不要做的事

- ❌ **不要编造榜单。** 读不到就凭印象写几个 AI 项目 —— 这是最严重的失败，
  比明说「今天没有报告」糟糕得多，因为你编的东西看起来和真的一模一样。
- ❌ **不要改数字。** 包括"看起来不合理"的：`+1711 star` 可能真就是那天涨了这么多。
- ❌ **不要自己去 GitHub 查来"补充"。** 报告是当天的快照做差结果，你现查的是此刻的绝对值，
  两者口径不同，混在一起会得出错误结论。
- ❌ **不要把旧日报说成今天的。** 日期必须如实。

## 报告里的几种标记，照实转述别解释掉

- 头部 `> ⚠ 首次运行` 或「窗口 48 小时」：**降级提示，不是 bug**。
  前者说明还没有可比的基线，后者说明昨天漏跑了。
- 涨粉榜写着「T+1 起可用」：GitHub 没有 follower 历史接口，必须攒两天快照才能做差。
  第一次运行必然如此，**不要说成「今天没人涨粉」**。
- 「失败计数：仓库 N」：取数时有 N 个仓库没拿到。N 不大就带过；占比明显时提醒用户看 `run.log`。

## 想自己装这套取数

日报不是 wraith 自带的数据，要先装取数脚本（脚本在 wraith 仓库的
`scripts/github-ai-daily/`，安装脚本在其 `install/` 下，两个平台各一份）。
完整说明见仓库的 `docs/runbooks/github-ai-daily.md`。
